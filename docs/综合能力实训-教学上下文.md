# 综合能力实训 · 教学上下文

给在本仓库继续开发的 agent。课堂案例是这个 WMS。学生大作业是另外 15 个选题，验收标准与这里对齐，不要在本仓库里做那 15 个题。

具体设计按内容块写在 `docs/备课/教案.md`。一共六个部分。第一部分（第 10 周）、第二部分（第 11 周）、第三部分（第 12、13 周）各只有一个分支，没有改良版。第四、第五部分各一个分支、各一个改良版。TraceId 放到第五部分再讲。

## 现状（main）

已有：注册登录、用户 CRUD、仓库–库区–库位（FR-01，Flyway V1–V6）、JWT、单测、Postman、Actuator、`docker-compose.dev.yml`（只有 MySQL + Adminer）。

没有：货品、库存、入库、出库、Redis、MinIO、Nginx、Prometheus、Grafana。

第 10 周学生不用 Docker：用自己的 MySQL，手动启动后端和前端。老师自己的 MySQL、Adminer 用 Compose 起，后端也手动启动，讲义截图按老师电脑来。Docker（镜像、容器、Compose、应用镜像、容器里的 `localhost`）放到第六部分部署时从头讲。TraceId 的代码可以先留在仓库里，开关默认关闭。第 10 周和第 12 周都不讲，第五部分排错与监控再讲它是什么、解决什么、代码在哪。

上学期已讲过的分层、JWT、库位 CRUD、Flyway、Postman、单测，不要再当成新功能重做。Docker 没讲过，放到第六部分。

## 课表

90 课时，第 10–16 周。10–14 周每周 6 课时（周一 1–2 节 + 周三 1–4 节）。15–16 周每周 30 课时（周一全天 8、周二 1–4 与 9–10 共 6、周三 1–4 共 4、周四全天 8、周五 1–4 共 4）。全天按 1–4 节 + 7–10 节。答辩只有 16 课时。

## 三次作业

- 作业一，个人，10%。第 10 周布置，第 11 周周三截止。前后端在本机跑起来，登录可用，核心表初稿，个人 Gitee。不要求 Redis。
- 作业二，个人，负责小组一个模块，20%。第 11 周布置，第 15 周周三截止。设计、开发、单测、模块报告。工程点三选一：第二部分的状态机或乐观锁、第三部分的缓存或锁、第四部分的文件。缺陷记录在第五部分写完再交。
- 作业三，团队，40%。第 15 周周三布置，第 16 周周二截止。集成、压测、全组一条异步链路、一类文件、Docker + Nginx + Linux。对应第四到第六部分。周二后冻结功能。

答辩抽问：超卖怎么防、消息怎么不重复、慢了怎么查、Nginx 做什么、哪个容器是 Redis、Grafana 上看到什么。

## 教法

老师上课分步骤讲清楚，不要求学生课上自己做。学生把代码下载下来，对照页面、前后端代码和数据库里的数据边看边学。讲义只讲这一部分新增的内容，用一个案例从页面讲到数据库，其余接口列出文件位置让学生课后自己看。

第一部分只讲正常功能，不留漏洞。第二部分只留乐观锁一个开关，老师关掉它演示两个人同时出库只扣一次库存，再打开演示一张被拒。第三部分起保留漏洞和改良版，由老师演示：同一个操作在漏洞一侧怎样出错，改良版怎样不出错。代码要能演示修复前和修复后，用开关、分支或分步提交，不要只留最终正确版本。

| 内容 | 先留的漏洞 | 现象 | 学生查什么 | 学生改什么 |
|------|------------|------|------------|------------|
| 货品 SKU | 编码可重复 | 两条相同编码 | 重复数据 | 唯一约束 |
| 库存表 | 数量写在货品上 | 两个库位时总数是错的 | 对不上的账面 | 改成货品+库位+数量+version |
| 入库 | 加库存和改状态不在一个事务 | 库存加了，单据仍未完成 | 半成功的单 | 合成一个事务 |
| 出库 | 不校验剩余数量 | 库存变负 | 负数行 | 数量校验 |
| 状态机 | 已完成还能改数量 | 单据和账面不一致 | 完成后的修改 | 拒绝非法状态 |
| 超卖 | 并发各自读到还有库存 | 两路一起出，库存变负 | 日志里的两次请求 | 本步只确认是并发 |
| 乐观锁 | 只有 @Transactional | 修完事务后并发仍超卖 | 两个事务都提交了 | 更新带 version |
| 事务边界 | 消息发在事务里 | 入库回滚了，流水还在 | 没有入库单却有流水 | 提交成功后再发消息 |
| Redis 缓存 | 改库不删缓存 | 页面还是旧库存 | Redis 与库不一致 | 更新后删缓存 |
| Redis 锁 | 挡不住同时通过库存检查 | 仍有一单不该成功 | 两单都过了检查 | 按货品+库位加锁 |
| 防重复提交 | 确认出库点两次 | 扣两次 | 同一单两条扣减 | 用单号挡住第二次 |
| Redis 异步 | 消费者不认单号 | 同一消息处理两次，流水两笔 | 重复流水 | 入库单号幂等 |
| MinIO | 文件在本机磁盘 | 换机器或进容器后 404 | 库里是本机路径 | 改存 object key |
| TraceId | 并发日志混在一起 | 看不出哪次把库存打负 | 对不上请求 | 日志加上 TraceId |
| 性能 | 无索引、一次查全表 | 查询超过 3 秒 | 慢查询、全表扫描 | 索引和分页 |
| Prometheus/Grafana | 没有指标 | 只知道变慢，不知哪条接口 | 压测曲线缺失 | 暴露指标，看出库耗时和拒绝次数 |
| Docker | 地址写 localhost | 容器里连不上数据库 | 容器日志 | 改成 Compose 服务名 |
| Nginx | 页面直连 8080 | 用服务器地址打开时接口失败 | 浏览器请求 | 改走 /api |
| Linux | 本机能开、服务器不能 | 端口或环境不一致 | docker ps 和日志 | 同一份 Compose 与 .env |

技术选型：Redis 不用 RabbitMQ；异步用 Stream 或 List，Pub/Sub 不合格。Zipkin 只演示。学生不自建告警、不手画全套 Grafana 仪表盘。Nginx 只做反代，不算业务。
