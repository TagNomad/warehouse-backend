第五部分 · 文件

第 15 周周二全天。入库单可以带一个附件。这一部分先把文件写在运行应用的那台机器上。「第五部分」和「第五部分改良版」用的是这一份讲义。改良版改的是代码：附件放进 MinIO，表里写对象 key，不再写这台机器的绝对路径。

上传走哪几层

POST /inbound-orders/{id}/attachments，表单字段名是 file。Controller 把文件名和字节交给 AttachmentService.save。Service 按入库单号建目录，把绝对路径写进 inbound_attachment.file_path。

GET /inbound-orders/{orderId}/attachments/{attachmentId} 按这一列去读文件。删掉那个路径上的文件，再下载就是 400，message 里是 FILE_NOT_FOUND。库里的路径还在。

对一下 Adminer 里 file_path 以这台机器的目录开头，不是 inbound/单号/文件名。

改良版改了这一块：附件放进 MinIO

改良版上 file-store 是 minio。上传写入桶 wms，对象 key 是 inbound/{orderNo}/{filename}。inbound_attachment.file_path 存的是这个 key。下载按 key 去桶里取。换机器或进容器，同一个 key 还能下载。

对一下 表里的 file_path 是 inbound/单号/文件名，不再以本机目录开头。

改良版改了哪一块

这一部分现在的代码改良版上的代码
file-store 是 local。文件写在应用本机，file_path 是绝对路径。文件一删，下载就是 FILE_NOT_FOUND。minio。文件在桶 wms，file_path 是 inbound/{orderNo}/{filename}。

上传和下载的路径没变。Controller 仍把文件名和字节交给 Service。课堂上把改良版合并进第五部分，带过去的是这一块存储。
