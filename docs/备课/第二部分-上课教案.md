# 第二部分上课教案（第 11 周周一 1–2 节）

2 课时。打开 [第二部分-讲义.html](./第二部分-讲义.html)。货品的表、两行初始数据、创建和查询接口已经在项目里。这节不重讲登录，也不在黑板上把类从空文件写出来。顺着一次 `POST /skus` 看数据经过哪一层。学生自己的作业用 DeepSeek 或 Kimi 按讲义里那段要求生成，再对照数据流检查。

投影讲义里的图。不要在课堂上再打开这些文件对照，也不要再创建一次 SKU-001。第二次创建的 200 和 Adminer 里的多行已经截在讲义里。库现在只留启动时的两行。

## 业务（约 15 分钟）

仓库、库区、库位是「放在哪」。`WH-001` 下面有 `A-01-01`、`A-01-02`、`B-01-01`。货品是「是什么货」，表里已经有轴承和螺栓。数量和出入库今天不讲。

分层表用仓库那一列点到为止。告诉学生登录第一部分已经做过，这里只在 Swagger 里贴一次 token。

## 顺着创建看数据（约 40 分钟）

先 `GET /skus`，看到 `SKU-001`、`SKU-002`。Adminer 的 `sku` 表是同样两行。说明这是启动时写进去的。

按讲义里的图讲创建 `SKU-003` 的走向，不用在课堂上再提交：

1. `SkuCreateRequest`：只有三个字符串。
2. `SkuController.create`：三个字段交给 Service，不写 SQL。
3. `SkuService.create`：补 `createdAt`，调用 Mapper。
4. `SkuMapper.insert` 和 `V7`：`id` 在数据库里出现。

每张图问这一层手里的数据比上一层多了什么。

讲义里那段话可以投出来。说明作业里新模块这样交给 DeepSeek 或 Kimi，生成后用同样的顺序检查，不要让它在 Controller 里写 SQL。

## 第二次创建的结果（约 25 分钟）

讲义里已经有第二次 `POST /skus` 的 200，以及 Adminer 里 id 1、3、4 都是 `SKU-001`。问这几行算不算同一种货。

接着看四张对照图：仓库表的 `UNIQUE KEY`，货品表没有；`WarehouseService.create` 插入前查到就拒绝，`SkuService.create` 直接 `insert`。

改良版里查重和唯一索引已经写好。投影讲义「改掉之后」的三张代码图，以及再次提交 SKU-001 得到 400 的那张图。
