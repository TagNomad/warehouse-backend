# 第二部分上课教案（第 11 周周一 1–2 节）

2 课时。应用容器已经能登录。这节前大约 50 分钟复习代码分层和 Swagger，后大约 40 分钟做货品编码重复。课堂上打开 [第二部分-讲义.html](./第二部分-讲义.html)。

仓库里现在的货品是缺陷版：`sku.code` 只有普通索引，`SkuService.create` 不查重。不要事先把唯一索引加上。学生自己加下一条迁移，并在插入前拒绝重复编码。

## 先看一次登录怎么走（约 25 分钟）

打开 `AuthController.login`。方法里只有对 `authService.login` 的调用，没有 SQL。

按讲义的表让学生在仓库里指出六个包。问一句：为什么不在 Controller 里写 SQL。答案是 Controller 只接请求和返回，查表在 Mapper，业务在 application。

仓库、库区、库位是同一套切法。后面的货品也按这个加，不新发明一层。

## 用 Swagger 走一遍（约 25 分钟）

打开 `http://localhost:8080/swagger-ui.html`。

1. `POST /auth/login`，账号 `admin`，密码 `Admin@123`。应是 200，里面有 token。
2. 右上角 Authorize，只贴 token，不加 `Bearer`。
3. `GET /warehouses/list`，`current` 填 1，`pageSize` 填 10。没授权是 401，授权后能看到 `WH-001`。

登录接口没有锁。用户、仓库、库区、库位、货品有锁。

## 货品编码可以重复（约 40 分钟）

先讲漏洞：两条货品都叫 `SKU-001` 时，后面的入库和出库不知道扣的是哪一条。

让学生打开两处，确认缺陷还在：

- `src/main/resources/db/migration/V7__create_sku_table.sql` 里是 `KEY idx_code (code)`，不是唯一索引。
- `SkuService.create` 直接 insert，没有按 code 查询。

然后按讲义在 Swagger 把 `SKU-001` 创建两次。Adminer 用服务器 `mysql` 打开 `sku` 表，应有两行相同编码、不同 id。

学生自己改，不要改已经执行过的 V7：

1. 新增 `SkuMapper.getByCode`。
2. `SkuService.create` 在插入前查到已有编码就抛 `BusinessException("SKU_CODE_DUPLICATED", "SKU_CODE_DUPLICATED：货品编码已存在：" + code)`。
3. 新增 `V8__sku_code_unique.sql`，删掉普通索引，加上唯一索引。
4. Adminer 里先删掉重复行，只留一条 `SKU-001`。表里有重复行时，唯一索引加不上去，应用会起不来。
5. 重建应用容器：`docker compose -f docker-compose.dev.yml up -d --build app`。源码在镜像里编译，只改电脑上的文件不会进正在跑的容器。

验收：再创建一次 `SKU-001`，响应是 400，message 里有 `SKU_CODE_DUPLICATED`。`sku` 表仍然只有一行这个编码。

这节不做库存，不做多规格。库存是周三的第三部分。
