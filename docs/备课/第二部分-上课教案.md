# 第二部分上课教案（第 11 周整周）

6 课时。投影 [第二部分-讲义.html](./第二部分-讲义.html)。「第二部分」和「第二部分改良版」用的是这一份讲义。两个分支的 Java 代码相同，改良版上不同的是 `application.yaml` 和 `docker-compose.dev.yml` 里 `sku-code-check`、`inbound-stock` 两个开关的值（讲义第 4 节的差别图）。

课前：`docker compose -f docker-compose.dev.yml up -d --build`，应用在容器里，占本机 8080。Adminer `http://localhost:8081` 能登录。按讲义第 9 节清空入库表、删掉多余的货品。

## 周一：货品（约 2 课时）

1. 讲义第 1–2 节：上学期的仓库、库区、库位；分层表用仓库那一列点到为止。Swagger 里登录、Authorize 只演示一次。
2. 第 3 节只看 `V7` 和 `V3` 两张图：货品表 `code` 没有唯一键，仓库表有。
3. 第 4 节：开关从 yaml 到 `LessonSwitches` 到 Service；容器里由 Compose 的变量盖过。
4. 第 5 节按 Request → Controller → Service → Mapper 讲创建货品，对照字段表。学生照着写一遍。`onHand` 为什么是 `null` 可以问一句。
5. 实验第 1–2 步，接第 10 节漏洞一：第二次 200，Adminer 两行 `SKU-001`；加一行 `SKU-001`，`skuId` 是 1。学生自己写分组计数的 SQL。
6. 对照改良版：`APP_LESSON_SKU_CODE_CHECK=on APP_LESSON_INBOUND_STOCK=location docker compose -f docker-compose.dev.yml up -d --force-recreate app`，同一个请求 400。讲「Service 先查」和「表上唯一索引」各挡哪一种情况，唯一索引第三部分加。

## 周三：入库（约 4 课时）

1. 第 3 节其余三张表：`on_hand`、入库单和行、`inventory`。
2. 第 6–8 节按三个接口讲。新建草稿和加一行两个分支相同；完成时只有第 73–77 行两条路。学生照着写。
3. 实验第 3–5 步，接第 11 节漏洞二：响应都是 200，差别在 Adminer：`on_hand` 18、`inventory` 无数据。问「A-01-01 上有多少」。学生自己从 `inbound_order_line.location_id` 追到 `complete` 第 77 行。
4. 对照改良版（同上一条命令），再跑第 3–6 步：`inventory` 两行，同一个格子再进一次还是一行，`version` 加一。
5. 第 12 节收束，第 13 节跑 `./mvnw test -Dtest='SkuInbound*PathTest'`。

## 重温 Pull Request（周三留下约 20 分钟）

讲义第 14 节。教师在 Gitee 上把「第二部分改良版」合并进「第二部分」：Fetch，切到改良版，Push，网页新建 Pull Request（源分支改良版，目标分支第二部分），网页点合并。学生把 Current Branch 换成第二部分，Pull origin。全班只合这一次。合并带过去的是四行开关值，讲义两边已经是同一份。

做完提醒：执行第 9 节最后那条 `DELETE`，库里只留一行 `SKU-001`，第三部分的 `V8` 才能执行。应用容器按当前分支的默认值重建一次：`docker compose -f docker-compose.dev.yml up -d app`。
