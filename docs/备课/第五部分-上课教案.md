# 第五部分上课教案（第 15 周周二全天）

6 课时。投影 [第五部分-讲义.html](./第五部分-讲义.html)。「第五部分」和「第五部分改良版」用的是这一份讲义。两个分支的 Java 代码相同，改良版上不同的是 `application.yaml` 和 `docker-compose.dev.yml` 里 `file-store`、`file-key` 两个开关的值（讲义第 4 节的差别图）。

课前：`docker compose -f docker-compose.dev.yml up -d --build minio app`，应用跑在容器里，占本机 8080。浏览器打开 `http://localhost:9001`，`minioadmin` / `minioadmin` 能登录。官方 `minio/minio` 镜像已拉不到，Compose 里用的是社区构建 `pgsty/minio`，控制台标题是 SILO。按讲义第 7 节清空三张表，准备 `note1.txt`、`note2.txt`。

## 上午

1. 讲义第 1–3 节：为什么文件内容不进数据库，表里只记「去哪找」。起 MinIO，看控制台。`V14` 和上传大小。
2. 第 4 节：两个开关；这一部分在容器里跑，起作用的是 Compose 里的值。
3. 第 5 节上传接口按 Controller → Service → 磁盘或 ObjectStore → Mapper 讲，讲清 `multipart/form-data` 和 `curl -F`、Postman 的 form-data。学生照着写一遍。
4. 第 6 节下载接口：`Content-Type`、`Content-Disposition`，附件要核对属于路径上的那张单。

## 下午

1. 实验顺序第 1、4、5 步，接第 8 节漏洞一：上传后能下载；`docker exec pro-skill-app ls -l /app/data` 看到文件在容器里；`--force-recreate app` 以后 `/app/data` 不在了，下载 `FILE_NOT_FOUND`，Adminer 里路径还在。讲容器磁盘是一次性的、多实例各有各的磁盘。
2. 对照改良版：`APP_LESSON_FILE_STORE=minio APP_LESSON_FILE_KEY=unique docker compose -f docker-compose.dev.yml up -d app`（改良版上直接 `up -d app`），同样的步骤重建后照样下载，控制台里能看到对象。讲表里为什么记 key 而不是带主机的地址。
3. 实验顺序第 2、3 步，接第 9 节漏洞二：同名 `note.txt` 两次，1 号下载到第二张；`../../escape.txt` 写到 `/app/data`。对照改良版：随机名，原名仍在 `file_name`。
4. 第 10 节收束，第 11 节跑 `./mvnw test -Dtest='Attachment*PathTest'`。
5. 第 12 节：把「第五部分改良版」合并进「第五部分」，只合并这一次。合并带过去的是开关值，讲义两边已经是同一份。

做完实验，应用容器按当前分支的默认值重建一次：`docker compose -f docker-compose.dev.yml up -d app`。
