# 综合能力实训 · 备课教案

课堂案例是这个 WMS。学生自己的大作业是另外 15 个选题，验收标准和这里对齐，不要在本仓库里做那 15 个题。

这份教案按六个部分写。第一部分（第 10 周）、第二部分（第 11 周）、第三部分（第 12、13 周）、第四部分（第 14 周）各只有一个分支，没有改良版。第五、第六部分还没有分支，下面先写计划。后一部分只用前一部分已经跑通的结果。

## 教法

每一块都按这四步，不要先把正确实现交给学生：

1. 讲清不这么设计的漏洞。
2. 项目里先留着这个错，按下面的操作就能复现。
3. 学生自己查：日志、库、页面。TraceId 从第五部分才用来串一次请求。
4. 学生自己改。同一操作不再出错。

代码里同时留缺陷路径和修复路径。第二到第四部分每个案例一个开关，写在 `application.yaml` 的 `app.lesson` 下，默认是修好的一侧，老师上课拨到另一侧演示。第五部分排错时，把对应开关拨回缺陷路径。

开关都写在 `application.yaml` 的 `app.lesson` 下。库上的约束（唯一索引、乐观锁条件）用前后两次迁移或两次提交演示，不靠开关把已经加上的唯一索引再关掉。

## 本分支留下什么

留下能跑的基础，第 10 周用来接新内容：

- 注册登录、JWT、用户 CRUD
- 仓库–库区–库位，Flyway V1–V6
- 演示账号 `admin` / `Admin@123`，仓库 `WH-001`（华东原料仓），库位 `A-01-01`、`A-01-02`、`B-01-01`
- 单测、`api-contract/http`
- 老师的 MySQL、Adminer 用 Compose 起；学生用自己的 MySQL，前后端在本机手动启动
- 分层约定：`layered-architecture.md`

上学期的用户 CRUD 讲义、FR-01 作业教案、Postman 性能集合、个人介绍材料，已从本分支删除。那些内容不再当新课讲。

## 不做

盘点、FIFO、移库、复杂报表。异步不用 RabbitMQ，也不用 Redis Pub/Sub，用 Stream。Zipkin 只演示。学生不自建告警，不手画全套 Grafana 仪表盘。Nginx 只做反代，不算业务。

### 第一次课 · 拿到代码，把系统跑起来（周一，2 课时）

3. 后端：学生用自己的 MySQL，账号密码不是 root 时写 `application-local.properties`；IDEA 或 `./mvnw spring-boot:run` 启动，库和表自动建好。老师的 MySQL 在 Docker 里，后端同样手动启动。
4. 前端：`npx pnpm@9 install`、`npx pnpm@9 dev`。
5. 一个案例：点「库区库位」，从前端讲到三张表。
6. 老师演示分支、提交、Pull Request。

不讲 Docker、TraceId。作业一在这周布置。

## 第二部分 出库与并发（第 11 周，6 课时）

学生讲义 [第二部分-讲义.html](./第二部分-讲义.html)，上课按 [第二部分-上课教案.md](./第二部分-上课教案.md)。分支「第二部分」，没有改良版。代码按正确写法跑：出库前检查剩余够不够，已完成的单不能改行，入库流水和入库同一个事务。只留乐观锁一个开关 `optimistic-lock`，默认 `on`。

### 第一次课 · 出库（周一，2 课时）

一个案例：从 A-01-01 出 4 个垫圈。新建出库单、加一行、完成出库，重点跟着「完成出库」从前端讲到 `inventory`：10 变成 6，`version` 变成 1。再出 20 个，返回 `INSUFFICIENT_STOCK`。

### 第二次课 · 并发（周三，4 课时）

格子上只剩 1 个，两张单各出 1 个同时完成。后端启动参数加 `--app.lesson.optimistic-lock=off --app.lesson.outbound-read-pause-ms=3000`，页面上「同时完成勾选的单」：两张都成功，库存 0，`version` 0，丢失更新。去掉 `optimistic-lock=off` 重启再做：一张 `STOCK_CONFLICT`，`version` 1。讲 `WHERE id = ? AND version = ?` 和影响行数为 0 时报错。失败的一路直接拒绝，不做自动重试。

改一行的数量（只有草稿能改）、入库流水（和入库同一事务）不展开，讲义里列出代码位置，学生自己看。

## 第三部分 Redis（第 12 周、第 13 周，12 课时）

学生讲义 [第三部分-讲义.html](./第三部分-讲义.html)，上课按 [第三部分-上课教案.md](./第三部分-上课教案.md)。分支「第三部分」，没有改良版。讲义开头先讲 Redis 是什么、这里为什么用、怎么装（老师 Docker，学生 Windows 版 Redis 5.0 以上）。每个案例一个开关，默认是正确写法，老师在 IDEA 启动参数里拨到另一侧演示问题。

| 课 | 案例 | 开关拨到另一侧时 |
|----|------|------------------|
| 第 12 周周一 | 缓存：查库存先查 Redis，出库后删缓存 | `cache-evict=off`：出库后还查到旧数 |
| 第 12 周周三 | 锁：两张单同时出同一个格子 | `stock-lock=after-check`：库存够也有一张 `STOCK_CONFLICT` |

| 第 13 周周一 | 异步消息：入库完成 `XADD`，消费者写 `inbound_notice` | — |

| 第 13 周周三 | 消费者按消息编号去重 | `consume-once=off` + `consume-fail-before-ack=true`：重投后通知写两行 |

## 第四部分 文件 MinIO（第 14 周，6 课时）

学生讲义 [第四部分-讲义.html](./第四部分-讲义.html)，上课按 [第四部分-上课教案.md](./第四部分-上课教案.md)。分支「第四部分」，没有改良版。讲义开头先讲 MinIO 是什么、为什么文件不放后端机器上也不放表里、怎么装（老师 Docker，学生 Windows 上的 Silo）。只做入库单附件：`POST /inbound-orders/{orderId}/attachments` 上传，`GET /inbound-orders/{orderId}/attachments/{attachmentId}` 下载。每个案例一个开关，默认是正确写法，老师在 IDEA 启动参数里拨到另一侧演示问题。

| 课 | 案例 | 开关拨到另一侧时 |
|----|------|------------------|
| 第 14 周周一 | 给 IN-1 传一张收货单，从前端讲到 `inbound_attachment` 和桶 `wms`；再下载回来 | — |
| 第 14 周周三 | 文件放在哪 | `file-store=local`：表里记本机绝对路径，把 `data/attachments` 改名模拟换机器，下载 `FILE_NOT_FOUND`；默认 `minio` 记 key，照样下载 |

## 第五部分 排错与监控（第 15 周周三至周五）

16 课时。还没有分支和讲义，下面是计划：打开 TraceId、列表按页返回、记下出库耗时和拒绝次数。TraceId 从这一部分才讲。作业二的缺陷记录在这三天里写完。作业三在周三布置。

### TraceId

是什么：这一次 HTTP 请求的编号。同一次完成里的「读到数量」和「把数量改成」带着同一个号。

解决什么：两张出库单几乎同时完成，四行日志穿在一起。没有这个号，圈不出哪一次读到了旧数量。

怎么实现：不在 Controller 里。

1. `observability/TraceIdFilter.java`。开关打开时读请求头 `X-Trace-Id`，没有就生成 UUID，放进 MDC，并写回响应头。请求结束清掉这个键。
2. `application.yaml` 的日志格式 `[%X{traceId}]`。`app.lesson.trace-id` 在前面的部分保持 `off`，括号是空的。
3. `docker-compose.dev.yml` 的 `APP_LESSON_TRACE_ID`。改开关只重建应用容器。

然后把第二部分的乐观锁、第三部分的删缓存和消费幂等拨回缺陷路径。学生用这个号把一次请求、库和 Redis 串起来，再拨回修复路径。

### 慢查询

先留的错：`inventory-query=full`。`GET /inventories/list` 不带 `LIMIT`，带了 `page` 和 `size` 也返回全表。

学生查：`EXPLAIN` 或这次查询的耗时。

修好之后：`inventory-query=page`。列表按页返回。`(sku_id, location_id)` 唯一键继续留着。

### Prometheus

先留的错：`metrics=off`。Actuator 只暴露 `health` 和 `info`。出库被拒绝时不计次数。

修好之后：`metrics=on`。计时 `wms.outbound.complete`，计数 `wms.outbound.rejected`。端点加上 `prometheus`。Grafana 用已经配好的面板，学生要能指出出库耗时和拒绝次数。不从空白面板画起，不做告警。

## 第六部分 部署（第 16 周周一至周二）

14 课时。把 Compose、Nginx、Linux 接在这两天里讲完。镜像和「localhost 连不上 MySQL」已经在第一部分做过，这里不再新讲 Dockerfile。

Docker 从这一部分开始讲：镜像、容器、Compose、端口映射、数据卷、应用的 Dockerfile，以及容器里的 `localhost` 指容器自己、容器之间用服务名互相找。前面几部分学生都在本机手动启动。

### 收进同一份 Compose

漏洞：Redis 或 MinIO 的地址在容器里写成 `localhost`。应用容器去连自己。

学生查：`docker ps` 里 Redis、MinIO 是 Up，应用日志里的主机名是 `localhost`。

学生改：改回服务名 `redis`、`minio`，仍用第一部分的 `docker-compose.dev.yml`。

### Nginx

Nginx 加进同一份 Compose。`/` 给页面，`/api` 转到后端。页面不再直连 `8080`。

### Linux

本机能开，是因为开发机有本机端口和本机 Docker。拷到 Linux 后，这些前提没有了。

学生改：数据库、Redis、MinIO、应用端口、密码都从 `.env` 读取。JDBC 主机保持服务名 `mysql`。开发机和 Linux 用同一份 Compose，只允许 `.env` 里的端口和密码不同。周二下课前冻结功能。
