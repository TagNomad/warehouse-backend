# 第一部分上课教案（第 10 周）

6 课时。学生以前没学过 Docker。仓库里的 MySQL 和 Adminer 是教师自己写进 Compose 的，这周当新课讲。

课堂上用浏览器打开 [第一部分-讲义.html](./第一部分-讲义.html)，全屏。页顶先选 macOS 或 Windows。顺序是：先讲 Git 和 GitHub Desktop，把课堂仓库克隆到本地，再讲 Docker 并把项目跑起来。最后做随堂测验：教师先在自己的 Gitee 仓库里演示一遍新建分支、提交、推送、网页 Pull Request、网页合并，学生看完再用自己的仓库做。不要推送到课堂仓库，也不做本地 merge、rebase。这份教案只留给教师看时间和四步怎么落。

周一 1–2 节：Docker 是什么，只启动 MySQL 和 Adminer。  
周三 1–4 节：把应用加进同一份 Compose，读 Dockerfile，确认能登录。TraceId 这天不讲。

这周结束时学生要能做到：说出镜像和容器的差别；用 Compose 拉起 MySQL 和 Adminer；在 Adminer 里改用服务名 `mysql` 看到表；应用容器用服务名 `mysql` 启动后登录成功；在自己的 Gitee 仓库里完成一次网页 Pull Request 并合并。

课堂账号：`admin` / `Admin@123`。演示仓库：`WH-001`。数据库：`pro_skill`，`root` / `root`。

## 周一 1–2 节：Docker、MySQL、Adminer

先不要启动应用容器。周一只碰 MySQL 和 Adminer。

开课先投讲义开头「先看页面：这两次课要做出什么」（约 5 分钟）：教师电脑上前端和后端已经跑着，打开 `http://localhost:5173` 登录，点仓库管理里 WH-001 的「库区库位」。告诉学生周三下课前自己电脑上也要跑出这一页，再按那张表从上往下讲。

### 先讲清楚（约 20 分钟）

三句话：

- **镜像**是打包好的软件，例如 `mysql:8`、`adminer:4`。它还没在跑。
- **容器**是镜像跑起来的那一个。停掉容器，里面没写进数据卷的东西就没了。
- **Compose** 用一个文件描述要一起启动哪些容器。文件是 `docker-compose.dev.yml`。

打开这个文件，只看 `mysql` 和 `adminer` 两段，带着学生读这几个字段：

| 字段 | 在这份文件里是什么 |
|------|-------------------|
| `image` | 用哪个现成镜像。MySQL 用 `mysql:8`，Adminer 用 `adminer:4` |
| `container_name` | 容器名字：`pro-skill-mysql`、`pro-skill-adminer` |
| `ports` | 左边是自己电脑的端口，右边是容器里的端口。MySQL 是 `3306:3306`。Adminer 是 `8081:8080`，所以浏览器开 `8081` |
| `environment` | 给容器的设置。数据库密码是 `root`，库名是 `pro_skill` |
| `volumes` | 数据卷。MySQL 的表存在卷 `pro-skill-mysql-data` 里，容器删了数据还在 |
| `depends_on` | Adminer 等 MySQL 健康检查通过再启动 |

先别讲应用那段。告诉学生：后面 Redis、MinIO 也是往这个文件里加一段，写法就是今天这两段。

请学生打开 Docker Desktop。终端执行：

```bash
docker version
```

能看到 Client 和 Server 两段，才算 Docker 已经在跑。看不到 Server，就先把 Docker Desktop 打开，等它不再转圈。

### 让项目自己出问题（约 25 分钟）

在仓库根目录只启动这两个服务：

```bash
docker compose -f docker-compose.dev.yml up -d mysql adminer
docker compose -f docker-compose.dev.yml ps
```

学生要看到 `pro-skill-mysql` 是 healthy，`pro-skill-adminer` 是 Up。浏览器打开 `http://localhost:8081`。

登录时先故意填错服务器：

| 字段 | 先填这个 |
|------|----------|
| 系统 | MySQL |
| 服务器 | `localhost` |
| 用户名 | `root` |
| 密码 | `root` |
| 数据库 | `pro_skill` |

登录失败。Adminer 在自己的容器里，它写的 `localhost` 是 Adminer 那个容器，不是旁边的 MySQL。

### 学生自己查（约 15 分钟）

让学生对照三样东西，先不要直接说答案：

- `docker compose ps` 里 MySQL 是不是 healthy
- Adminer 页面上服务器一栏填的是什么
- Compose 里 Adminer 的 `ADMINER_DEFAULT_SERVER` 写的是什么

文件里已经写了 `ADMINER_DEFAULT_SERVER: mysql`。页面如果被改成 `localhost`，就和文件不一致。

### 学生自己改（约 20 分钟）

服务器改成 `mysql`，其他不变，再登录。

能看到库 `pro_skill`。点开表，至少有 `tb_user`、`warehouse`、`flyway_schema_history`。`tb_user` 里有 `admin`。

再把服务器改回 `localhost`，确认又进不去；改回 `mysql`，确认又能看见表。这个错不需要改 Java。

常用命令留在黑板上：

```bash
docker compose -f docker-compose.dev.yml ps
docker compose -f docker-compose.dev.yml stop
docker compose -f docker-compose.dev.yml start
```

`stop` 之后数据还在。不要在这周执行 `down -v`，那会把数据卷删掉。

### 分组和作业一（剩余时间）

每组确定大作业选题，并指定谁负责作业二的模块。课堂案例全组跟着做。

作业一这周布置，第 11 周周三截止：项目能启动，Compose 能起 MySQL，登录可用，核心表初稿，个人 Gitee。不要求 Redis。登录要等周三把应用容器跑通之后才能自己交；周一先把 MySQL 和 Adminer 交到能看见 `tb_user`。

## 周三 1–4 节：应用容器

周一的 MySQL 和 Adminer 保持运行。这天把 `docker-compose.dev.yml` 里的 `app` 段打开。

### 先讲应用这一段（约 15 分钟）

应用没有现成的 `image: mysql` 这种公共镜像。`Dockerfile` 用项目源码打出一个镜像，Compose 里 `build: .` 就是在做这件事。容器名 `pro-skill-app`，端口 `8080:8080`。

先把 `Dockerfile` 投出来，大约 15 分钟，再执行下面的 `--build`。文件分两段：第一段 `AS build` 用 JDK，在镜像里跑 `./mvnw package`；第二段只留 JRE，把 jar 拷成 `app.jar`。最后一行 `ENTRYPOINT ["java", "-jar", "app.jar"]` 才是容器启动命令。所以 Compose 里看不到 `mvnw spring-boot:run`。学生电脑不用单独装 Maven。源码没改时，后面的启动不用再加 `--build`。

`depends_on` 写了等 MySQL 健康。数据库主机来自环境变量 `APP_LESSON_DATASOURCE_HOST`，这份文件里的默认值是 `mysql`，和周一 Adminer 改对的服务器名一样。`docker-compose.localhost.yml` 会把它改回 `localhost`，这节不用。那个文件留到第 15 周排错时再叠上去。

### 直接启动应用（约 20 分钟，含第一次构建）

```bash
docker compose -f docker-compose.dev.yml up -d --build app
docker compose -f docker-compose.dev.yml ps
```

第一次会构建镜像，要等。构建完之后 `pro-skill-app` 变为 healthy。只动 `app`，MySQL 和 Adminer 继续跑。

验收：

```bash
curl -s http://localhost:8080/actuator/health
```

里面有 `"status":"UP"`。这里的 `localhost:8080` 是自己电脑的浏览器访问映射出来的端口。应用在容器里面连数据库用的是服务名 `mysql`。这两句分开讲，不要再把错误主机名跑一遍。

登录：

```bash
curl -s -X POST http://localhost:8080/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123"}'
```

返回里有 token。Swagger 的点法留到第 11 周周一，地址是 `http://localhost:8080/swagger-ui.html`。

### 接上前端（约 10 分钟）

讲义「第二次课最后：用前端页面登录」。前端仓库 `warehouse-frontend` 切到「第一部分」分支，`npx pnpm@9 install`、`npx pnpm@9 dev`，打开 `http://localhost:5173` 用 admin 登录。投影 `vite.config.ts` 第 63–67 行：页面发 `/api/...`，Vite 去掉 `/api` 转给 8080。点仓库管理里 WH-001 的「库区库位」，让学生记下三个库位编码，第二部分入库要用。前端代码不要求学生写。

日志里的空中括号这节不用讲。TraceId 放到第 15 周周三（第六部分）排错时再讲它是什么、解决什么、代码写在哪。

### 收束（剩余时间）

学生笔记里留三样东西：Adminer 填 `localhost` 失败、填 `mysql` 能看见 `tb_user` 的截图；应用健康检查 UP 和登录返回 token；前端页面展开 WH-001 库区库位的截图。作业一仍是第 11 周周三截止。

## 这周用到的开关

| 什么 | 缺陷怎么出现 | 改对之后 |
|------|----------------|----------|
| Adminer 的服务器 | 页面填 `localhost` | 填服务名 `mysql` |
| `APP_LESSON_DATASOURCE_HOST` | 周一 Adminer 填 `localhost`。`docker-compose.localhost.yml` 留到第 15 周，这节不用 | 应用和 Adminer 都用服务名 `mysql` |

数据库主机名只重新创建 `app` 容器，不用为了改主机名重新构建镜像。第一次把应用加进来时才需要 `--build`。TraceId 的开关这周不动。
