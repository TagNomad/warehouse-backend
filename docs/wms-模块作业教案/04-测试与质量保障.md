# FR-01 仓库与库位管理 — 测试与质量保障（报告第 4 章）

## 一、为什么要做测试？

开发完功能不等于「能用且可靠」。测试是在代码上线前帮我们发现问题的「安全网」。


| 测试类型         | 测什么                              | 本模块示例                                |
| ------------ | -------------------------------- | ------------------------------------ |
| **单元测试**     | 一个类/方法，隔离依赖                      | `WarehouseService.create()` 编码重复时抛异常 |
| **集成测试**     | 多个层协作（Controller + Service + DB） | `POST /warehouses` 真正写入 H2 数据库       |
| **系统测试（黑盒）** | 从用户视角验证需求                        | 用 Postman 走完整「建仓→建区→建位→看树」流程         |


课件中的 **FIRST 原则**（Fast / Independent / Repeatable / Self-validating / Timely）记住一句：**测试要快、互不干扰、可重复跑、结果自动判定、尽量与代码同步写。**

**为什么测试用 H2 而不是 MySQL？**  
课件推荐：测试不应污染开发库。H2 是内存数据库，跑完即销毁，配合 `@Transactional` 每条用例自动回滚。

## 四、单元测试手把手（Mockito）

### 4.1 核心思路

`WarehouseService` 依赖 `WarehouseMapper` 等组件。单元测试**不连真数据库**，用 Mockito **假装** Mapper 的返回值，只验证 Service 的业务规则。

```
Given  准备：when(mapper.getByCode("WH-001")).thenReturn(null)
When   执行：service.create(input)
Then   断言：assertEquals("WH-001", result.getCode())
        验证：verify(mapper).insert(...)
```

### 4.2 关键注解


| 注解                                    | 作用                    |
| ------------------------------------- | --------------------- |
| `@ExtendWith(MockitoExtension.class)` | 启用 Mockito            |
| `@Mock`                               | 创建假 Mapper            |
| `@InjectMocks`                        | 把 Mock 注入被测 Service   |
| `@Spy` + MapStruct                    | Converter 用真实实现，测转换逻辑 |


### 4.3 必测业务场景（FR-01）

**仓库 `WarehouseService`**


| 场景    | 期望                                               |
| ----- | ------------------------------------------------ |
| 创建成功  | 默认状态 `ENABLED`                                   |
| 编码重复  | `BusinessException`，code=`WAREHOUSE_CODE_EXISTS` |
| 删除有库区 | 拒绝，code=`WAREHOUSE_HAS_ZONES`                    |
| 库位视图  | 返回 仓库→库区→库位 树                                    |


**库区 `WarehouseZoneService`**


| 场景    | 期望                    |
| ----- | --------------------- |
| 仓库不存在 | `WAREHOUSE_NOT_FOUND` |
| 编码重复  | `ZONE_CODE_EXISTS`    |
| 删除有库位 | `ZONE_HAS_LOCATIONS`  |


**库位 `WarehouseLocationService`**


| 场景      | 期望                             |
| ------- | ------------------------------ |
| 占用库位改状态 | `LOCATION_OCCUPIED`            |
| 占用库位删除  | `LOCATION_OCCUPIED`            |
| 详情查询    | 聚合 location + zone + warehouse |


### 4.4 示例代码片段

打开 `WarehouseServiceTest.java`，找到 `@DisplayName("创建仓库失败：编码已存在")`：

```java
@Test
@DisplayName("创建仓库失败：编码已存在")
void create_codeExists_throws() {
    // Given
    when(warehouseMapper.getByCode("WH-TEST")).thenReturn(new WarehouseEntity());

    // When & Then
    BusinessException ex = assertThrows(BusinessException.class,
            () -> warehouseService.create(createInput));

    assertEquals("WAREHOUSE_CODE_EXISTS", ex.getCode());
    verify(warehouseMapper, never()).insert(any());
}
```

**练习**：仿照此用例，为 `WarehouseZoneService.create()` 补一个「库区编码重复」测试（项目中已写好，请阅读并运行）。

## 五、集成测试手把手（Spring Test + MockMvc）

### 5.1 与单元测试的区别


|           | 单元测试 | 集成测试                 |
| --------- | ---- | -------------------- |
| Spring 容器 | 不启动  | `@SpringBootTest` 启动 |
| 数据库       | Mock | H2 真写入               |
| HTTP      | 不经过  | `MockMvc` 模拟请求       |


### 5.2 关键注解

```java
@SpringBootTest
@AutoConfigureMockMvc          // Spring Boot 4 需额外依赖 webmvc-test
@ActiveProfiles("test")        // 加载 application-test.yaml
@Transactional                 // 每条用例结束回滚数据
```

### 5.3 带 JWT 的请求

本系统接口需要登录。集成测试先调登录接口拿 token：

```java
String token = TestAuthHelper.obtainAdminToken(mockMvc);

mockMvc.perform(post("/warehouses")
        .header("Authorization", "Bearer " + token)
        .contentType(MediaType.APPLICATION_JSON)
        .content(warehouseJson))
    .andExpect(status().isOk());
```

### 5.4 集成测试覆盖场景


| 用例                    | 验证点               |
| --------------------- | ----------------- |
| `fullWarehouseFlow`   | 仓库→库区→库位→树形视图 全链路 |
| `createDuplicateCode` | 重复编码返回 400        |
| `unauthorizedAccess`  | 无 token 返回 401    |

## 十一、常见问题 FAQ

**Q：`mvn test` 报找不到 `@AutoConfigureMockMvc`？**  
A：Spring Boot 4 将该注解移到 `spring-boot-starter-webmvc-test`，`pom.xml` 已添加，注意 import 路径为 `org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc`。

**Q：集成测试报 admin 用户重复？**  
A：`data-test.sql` 使用 H2 的 `MERGE` 语句，可重复执行；若仍报错，检查是否手动改了 SQL。

**Q：单元测试通过但 Postman 失败？**  
A：单元测试不连 MySQL。Postman 测的是真实运行环境，请确认 Flyway 迁移已执行、token 未过期。

**Q：如何只跑 FR-01 测试？**

```bash
mvn test -Dtest=Warehouse*Test
```
