## 三、写 2.2 功能模块设计

### 3.1 章首段（复制）

> FR-01 采用 RESTful API + 分层架构，实现仓库、库区、库位三层主数据 CRUD，并提供库位树形视图与库位详情聚合查询。核心规则：各级编码在所属范围内唯一；删除上级须无下级；库位状态支持 AVAILABLE/DISABLED/OCCUPIED。

### 3.2 三个子模块职责

| 子模块 | Service 类 | 核心规则 |
| --- | --- | --- |
| 仓库 | WarehouseService | code 全局唯一；有库区不可删 |
| 库区 | WarehouseZoneService | code 同仓库内唯一；有库位不可删 |
| 库位 | WarehouseLocationService | code 同库区内唯一；OCCUPIED 不可删 |

### 3.3 状态设计

**仓库 / 库区**：ENABLED ↔ DISABLED  

**库位**：

```text
新建 → AVAILABLE（可用）
        ↕
      DISABLED（禁用）
      OCCUPIED（占用，后续入库模块写入）
```

### 3.6 完整接口设计（第 2 章必写）

所有接口需 JWT。基础 URL：`http://localhost:8080`

> 下表「设计理由」说明：**为何采用该 Method/URL**，以及**对应 FR-01 哪条需求或用例场景**（可与第 1 章图1-1 步骤、图1-2 用例对照）。

#### 仓库

| 功能 | Method | URL | 设计理由 |
| --- | --- | --- | --- |
| 创建仓库 | POST | `/warehouses` | 对应需求书 **CRUD + 输入（编号/名称/地址）**；图1-1 **步骤②**；REST 用 POST 创建集合资源；系统管理员完成基础建模第一步 |
| 仓库列表 | GET | `/warehouses/list` | 对应需求书 **输出「仓库列表」**；图1-1 **步骤⑦**、用例「分页查询仓库列表」；支持分页与 code/name/type/status 筛选，供管理员浏览与检索 |
| 仓库详情 | GET | `/warehouses/{id}` | 维护场景：编辑/停用前 **回填表单**；按主键精确查询单条主数据 |
| 更新仓库 | PUT | `/warehouses/{id}` | 对应 **CRUD 之修改**；图1-1 **步骤⑧**；修改名称、地址、停用（status）等；PUT 表示对已有资源的完整/部分更新 |
| 删除仓库 | DELETE | `/warehouses/{id}` | 对应 **CRUD 之删除**；图1-1 **步骤⑧**；**有库区则拒绝**（WAREHOUSE_HAS_ZONES），保证层级数据一致 |
| **库位视图** | GET | `/warehouses/{id}/tree` | 对应需求书 **输出「库位视图」**；图1-1 **步骤⑤**、用例「查看库位视图（树形）」；一次返回 **仓库→库区→库位** 树，避免前端多次请求拼装 |

#### 库区

| 功能 | Method | URL | 设计理由 |
| --- | --- | --- | --- |
| 创建库区 | POST | `/warehouses/{warehouseId}/zones` | 对应需求书 **库区编号、类型（存储区/拣货区）**；图1-1 **步骤③**；URL **嵌套在仓库下**，表达「库区从属于仓库」；路径参数明确父级，防止挂错仓库 |
| 仓库下库区列表 | GET | `/warehouses/{warehouseId}/zones/list` | **在某仓库内维护库区** 时的列表；创建库位前选库区、查看该仓分区结构 |
| 全局库区列表 | GET | `/warehouse-zones/list?warehouseId=` | **跨仓库管理** 场景；`warehouseId` 可选，支持按仓库筛选或查全部；与仓库嵌套列表互补，便于后台统一检索 |
| 库区详情 | GET | `/warehouse-zones/{id}` | 编辑/停用库区前 **回填**；维护单条库区主数据 |
| 更新库区 | PUT | `/warehouse-zones/{id}` | 对应 **CRUD 之修改**；图1-1 **步骤⑧**；修改名称、类型、停用等；编码同仓唯一性在 Service 校验 |
| 删除库区 | DELETE | `/warehouse-zones/{id}` | 对应 **CRUD 之删除**；**有库位则拒绝**（ZONE_HAS_LOCATIONS），与删除仓库规则对称 |

#### 库位

| 功能 | Method | URL | 设计理由 |
| --- | --- | --- | --- |
| 创建库位 | POST | `/warehouse-zones/{zoneId}/locations` | 对应需求书 **库位编号、规格**；图1-1 **步骤④**、图2-1 时序；嵌套在 **库区下**，表达三层结构；新建默认 status=AVAILABLE |
| 库区下库位列表 | GET | `/warehouse-zones/{zoneId}/locations/list` | 在 **指定库区内** 维护/浏览库位；规划货架、批量录入时的局部列表 |
| 全局库位列表 | GET | `/warehouse-locations/list?warehouseId=&zoneId=` | 对应图1-1 **步骤⑦**；支持按 **仓库或库区** 组合筛选；库管员跨区查可用库位、按状态筛选 |
| 库位详情 | GET | `/warehouse-locations/{id}` | 单条库位 **CRUD 详情**（仅库位表字段）；编辑、禁用前回填 |
| **库位完整详情** | GET | `/warehouse-locations/{id}/detail` | 对应需求书 **输出「库位详情」**；图1-1 **步骤⑥**、用例「查看库位详情」；**聚合库位+库区+仓库**，供入库/拣货前确认「这条库位在哪个仓哪个区」 |
| 更新库位 | PUT | `/warehouse-locations/{id}` | 对应 **CRUD 之修改/禁用**；图1-1 **步骤⑧**；OCCUPIED 时不可改为非占用状态 |
| 删除库位 | DELETE | `/warehouse-locations/{id}` | 对应 **CRUD 之删除**；**OCCUPIED 不可删**（LOCATION_OCCUPIED），避免破坏在途库存引用 |

**接口设计要点（可写入报告小结）**：

- **嵌套 URL**（`/warehouses/{id}/zones`、`/warehouse-zones/{id}/locations`）体现 **1 对多归属**，与 E-R 图一致。  
- **独立 list + 查询参数** 满足 **全局检索** 与 **局部维护** 两类界面。  
- **tree / detail** 两个读接口分别对应需求书两项 **专用输出**，与普通 CRUD 详情分离，减少前端拼装。

#### 创建库区请求体

```json
{
  "code": "Z-STORAGE-01",
  "name": "A区存储区",
  "type": "STORAGE"
}
```

`type` 枚举：`STORAGE`（存储区）、`PICKING`（拣货区）

#### 创建库位请求体

```json
{
  "code": "A-01-01",
  "name": "A区1排1位",
  "spec": "1.2m×1m×2m"
}
```

#### 库位视图响应结构（GET /warehouses/{id}/tree）

```json
{
  "warehouse": { "id": 1, "code": "WH-001", "name": "华东原料仓", ... },
  "zones": [
    {
      "zone": { "id": 1, "code": "Z-STORAGE-01", "type": "STORAGE", ... },
      "locations": [
        { "id": 1, "code": "A-01-01", "status": "AVAILABLE", ... }
      ]
    }
  ]
}
```

#### 库位详情响应（GET /warehouse-locations/{id}/detail）

```json
{
  "location": { "id": 1, "code": "A-01-01", ... },
  "zone": { "id": 1, "code": "Z-STORAGE-01", ... },
  "warehouse": { "id": 1, "code": "WH-001", ... }
}
```

#### 业务异常码

| 错误码 | 含义 |
| --- | --- |
| WAREHOUSE_CODE_EXISTS | 仓库编码重复 |
| WAREHOUSE_NOT_FOUND | 仓库不存在 |
| WAREHOUSE_HAS_ZONES | 仓库下有库区，不可删 |
| ZONE_CODE_EXISTS | 库区编码重复 |
| ZONE_NOT_FOUND | 库区不存在 |
| ZONE_HAS_LOCATIONS | 库区下有库位，不可删 |
| LOCATION_CODE_EXISTS | 库位编码重复 |
| LOCATION_NOT_FOUND | 库位不存在 |
| LOCATION_OCCUPIED | 库位占用中，不可删或改状态 |

### 4.2 表2-1 仓库表 (warehouse)

> 脚本：`V3__create_warehouse_table.sql`。下表「设计原因」说明各字段及主键/唯一键/默认值为何如此设置。

| 字段名 | 说明 | 类型 | 约束 | 设计原因 |
| --- | --- | --- | --- | --- |
| id | 主键 | BIGINT | PK, AUTO_INCREMENT | 代理主键，供库区/库位外键引用；自增由数据库生成，避免应用侧 ID 冲突 |
| code | 仓库编码 | VARCHAR(50) | NOT NULL, UK | 对应需求书「仓库编号」；**全局唯一**（`uk_code`），作为业务识别码，列表筛选与接口按编码查询 |
| name | 仓库名称 | VARCHAR(100) | NOT NULL | 对应需求书「名称」；列表、详情、库位视图树节点展示 |
| type | 仓库类型 | VARCHAR(50) | NOT NULL | 扩展设计：区分 RAW_MATERIAL / FINISHED_GOODS / TRANSFER 等，支持按类型筛选（`idx_type`） |
| address | 仓库地址 | VARCHAR(255) | NULL | 对应需求书「地址」；允许创建时暂缺，后续维护补充 |
| manager | 负责人 | VARCHAR(50) | NULL | 运维联系信息，非需求书必填项 |
| phone | 联系电话 | VARCHAR(20) | NULL | 同上，与负责人配套 |
| status | 状态 | VARCHAR(20) | DEFAULT 'ENABLED' | 设计补充：ENABLED/DISABLED；新建默认启用；停用后业务层校验「目标仓库须为启用状态」（`idx_status` 便于筛选） |
| capacity | 库容量 | INT | NULL | 扩展字段，预留容量规划；FR-01 可不填 |
| created_at | 创建时间 | DATETIME | DEFAULT CURRENT_TIMESTAMP | 审计字段，记录主数据首次入库时间 |
| updated_at | 更新时间 | DATETIME | ON UPDATE CURRENT_TIMESTAMP | 审计字段，任何 UPDATE 自动刷新，便于追溯变更 |

### 4.3 表2-2 库区表 (warehouse_zone)

> 脚本：`V4__create_warehouse_zone_and_location.sql`（库区部分）。与仓库 **1 对多**；外键 `fk_zone_warehouse`。

| 字段名 | 说明 | 类型 | 约束 | 设计原因 |
| --- | --- | --- | --- | --- |
| id | 主键 | BIGINT | PK, AUTO_INCREMENT | 代理主键，供库位表 `zone_id` 外键引用 |
| warehouse_id | 所属仓库 | BIGINT | NOT NULL, FK → warehouse(id) | 表达「库区归属哪个仓库」；**外键**保证引用仓库必须存在；`idx_warehouse_id` 加速按仓库查库区列表 |
| code | 库区编码 | VARCHAR(50) | NOT NULL, 与 warehouse_id 联合唯一 | 对应需求书「库区编号」；**同仓库内唯一**（`uk_warehouse_zone_code`），不同仓库可重复相同编码 |
| name | 库区名称 | VARCHAR(100) | NOT NULL | 界面展示用，如「A 区存储区」 |
| type | 类型 | VARCHAR(50) | NOT NULL, STORAGE/PICKING | 对应需求书「存储区/拣货区」；枚举由应用层校验 |
| status | 状态 | VARCHAR(20) | DEFAULT 'ENABLED' | 设计补充：与仓库一致，支持库区级停用（`idx_zone_status`） |
| created_at | 创建时间 | DATETIME | DEFAULT CURRENT_TIMESTAMP | 审计字段 |
| updated_at | 更新时间 | DATETIME | ON UPDATE CURRENT_TIMESTAMP | 审计字段 |

### 4.4 表2-3 库位表 (warehouse_location)

> 脚本：`V4__create_warehouse_zone_and_location.sql`（库位部分）。与库区 **1 对多**；外键 `fk_location_zone`。

| 字段名 | 说明 | 类型 | 约束 | 设计原因 |
| --- | --- | --- | --- | --- |
| id | 主键 | BIGINT | PK, AUTO_INCREMENT | 代理主键；库位详情、入库单等后续模块引用 |
| zone_id | 所属库区 | BIGINT | NOT NULL, FK → warehouse_zone(id) | 表达「库位归属哪个库区」；**外键**保证库区存在；`idx_zone_id` 加速树形视图按库区加载库位 |
| code | 库位编码 | VARCHAR(50) | NOT NULL, 与 zone_id 联合唯一 | 对应需求书「库位编号」；**同库区内唯一**（`uk_zone_location_code`） |
| name | 库位名称 | VARCHAR(100) | NULL | 可选展示名，如「A 区 1 排 1 位」 |
| spec | 规格 | VARCHAR(100) | NULL | 对应需求书「规格」，如货架尺寸 |
| status | 状态 | VARCHAR(20) | DEFAULT 'AVAILABLE' | 对应需求书「可用/禁用/占用」；默认 AVAILABLE；OCCUPIED 由后续入库模块写入；`idx_location_status` 便于按状态筛选 |
| created_at | 创建时间 | DATETIME | DEFAULT CURRENT_TIMESTAMP | 审计字段 |
| updated_at | 更新时间 | DATETIME | ON UPDATE CURRENT_TIMESTAMP | 审计字段 |

**status 枚举**：AVAILABLE / DISABLED / OCCUPIED（需求书明文；仓库/库区 ENABLED/DISABLED 为设计补充，见 §3.3）
