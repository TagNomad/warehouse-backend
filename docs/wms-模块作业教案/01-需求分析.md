| --- | --- |

## 二、三层结构（必须先搞懂）

```
仓库 (Warehouse)          例：WH-001 华东原料仓
  └── 库区 (Zone)         例：Z-STORAGE-01 A区存储区
        └── 库位 (Location)  例：A-01-01 A区1排1位
```

| 层级 | 业务含义 | 需求书输入 |
| --- | --- | --- |
| 仓库 | 物理仓，顶层归属 | 编号、名称、地址 |
| 库区 | 仓内分区（存储区/拣货区） | 库区编号、类型 |
| 库位 | 具体货架位置 | 库位编号、所属库区、规格、状态 |

### 3.1 写 1.1 业务流程分析

**总述（复制）**：

> FR-01 是 WMS 【基础建模】的第一步：系统管理员先创建仓库，再在仓库下划分库区，最后在库区下创建库位。后续入库、出库、盘点都依赖库位主数据。本流程不涉及库存数量变更，仅维护主数据。

**八个步骤**（与图1-1 一一对应）：

1. **① 登录**：JWT 认证（`POST /auth/login`）。  
2. **② 创建仓库**：录入 code、name、address 等（`POST /warehouses`）。  
3. **③ 创建库区**：在仓库下创建 STORAGE / PICKING 库区（`POST /warehouses/{id}/zones`）。  
4. **④ 创建库位**：在库区下创建库位，填写 spec，默认 AVAILABLE（`POST /warehouse-zones/{id}/locations`）。  
5. **⑤ 查看库位视图**：树形结构 仓库→库区→库位（`GET /warehouses/{id}/tree`）。  
6. **⑥ 查看库位详情**：聚合库位+库区+仓库（`GET /warehouse-locations/{id}/detail`）。  
7. **⑦ 分页查询列表**：仓库/库区/库位列表及筛选。  
8. **⑧ 修改 / 停用 / 删除**：有下级数据时拒绝删除（`WAREHOUSE_HAS_ZONES` 等）。

### 3.3 写 1.3 系统实体模型分析

**表1-5 实体对象分析表**（模版可能叫表1-4，按你 Word 编号统一即可）

| 实体类 | 封装信息说明 |
| --- | --- |
| 仓库 (Warehouse) | id、code、name、type、address、manager、phone、status、capacity、createdAt、updatedAt |
| 库区 (WarehouseZone) | id、warehouseId、code、name、type（STORAGE/PICKING）、status、createdAt、updatedAt；与仓库 **1 对多** |
| 库位 (WarehouseLocation) | id、zoneId、code、name、spec、status（AVAILABLE/DISABLED/OCCUPIED）、createdAt、updatedAt；与库区 **1 对多** |
| 库位视图 (WarehouseTree) | warehouse + zones: List&lt;WarehouseZoneNode&gt;；节点内含 zone + locations（查询聚合，非独立表） |
| 库位详情 (WarehouseLocationDetail) | location + zone + warehouse（查询聚合） |

### 3.4 写 1.4 非功能性需求

> **性能**：列表与树形查询响应 ≤ 2 秒。  
> **安全性**：JWT 鉴权；RBAC（系统管理员维护主数据）；参数化 SQL。  
> **数据一致性**：编码在所属范围内唯一；删除仓库前须无库区，删除库区前须无库位；OCCUPIED 库位不可删除。  
> **可维护性**：Flyway 管理 V3～V5 迁移脚本。
