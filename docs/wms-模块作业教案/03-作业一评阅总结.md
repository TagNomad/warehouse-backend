## 三、共性问题（按出现频率排序）

### 1. 主题定制不完整 — 最高频

**现象：** 登录页或侧栏已改组内主题，但 `index.html`、`router.ts`、页面标题仍写「**工单管理系统**」；或只改了中文标签，Flyway 种子、`session.store`、后端 `@PreAuthorize` 仍用 WMS 的 `WAREHOUSE_MANAGER / OPERATOR / BUSINESS`。

**影响：** 核心功能与规范项均扣分；答辩时易被追问「你的系统到底是什么」。

**改进建议：** 改主题时做 **四方对齐清单**：

```
登录页 / 侧栏 / index.html / router 标题
    ↓
前端 role 枚举 + 中文标签
    ↓
Flyway V2 种子数据 role 字段
    ↓
session.store 权限映射 + SecurityConfig hasRole
```

**典型反例：** 第 9 组多人 login 已是「渔业管理系统」，router 仍为工单；第 2 组高分同学 index 仍残留工单标题。

---

### 2. 前后端契约不一致 — 用户「编辑/详情」链路重灾区

**高频子问题：**


| 子问题                   | 典型表现                                         | 后果         |
| --------------------- | -------------------------------------------- | ---------- |
| 编辑密码语义冲突              | 前端留空=不改；后端 `password` 必填或无条件 `BCrypt.encode` | 编辑一次误改密码   |
| 字段名不一致                | 后端 `userId`，前端读 `id`；Create 响应无 `user` 包裹    | 详情/编辑预加载失败 |
| UpdateRequest 与 UI 脱节 | 后端要求旧密码/新密码/确认密码，或 `username` 必填但前端 PUT 不传   | 编辑接口 400   |
| Mapper 未更新 password   | `UserMapper.update` SQL 不含 password 列        | 填新密码无法落库   |
| status 未落库            | 前端有状态下拉，后端 update 忽略 status                  | 启用/禁用编辑无效  |


**改进建议：** 以课程 starter 的 `UpdateUserRequest` + `UserService.updateUser` 为基准，先跑通 **Postman / warehouse.http 同级用户接口**，再对接前端；编辑密码统一约定：**空字符串/null 表示不更新**。

---

### 3. 构建与交付质量 — 「IDE 能跑、命令行不行」

**高频问题：**

- `**mvn compile` 失败**：Lombok 未配置 `annotationProcessorPaths`（第 10 组高分同学亦出现；课程 starter 的 `pom.xml` 已有范例）
- `**npm run build` 失败**：未使用变量却 import（TS6196）、`tsconfig` 非法项（如 `ignoreDeprecations: "6.0"` → TS5103）、vue-tsc 与 TS 版本不兼容
- **提交 `node_modules` / `target` / `.idea` / `dist`**：仓库体积膨胀、跨平台 clone 后构建失败
- **敏感信息入库**：`application.yml` 或 `application-local.properties` 含真实数据库密码

**改进建议：** 交作业前在本机执行固定检查：

```bash
./mvnw clean compile -DskipTests
cd frontend-web-starter && npm ci && npm run build
git status   # 确认无 node_modules、target、.idea
```

---

### 4. 安全链路缺失或「假安全」

**现象：**

- 完全 **无 JWT**：登录只返回 User 或字符串，Security 全 `permitAll`
- **前端假 token**：`localStorage` 存 `'token-' + Date.now()`，后端不校验
- **明文密码**：登录 `equals` 明文，种子数据未 BCrypt
- **API 泄露 password**：列表/登录响应带 BCrypt 哈希（仅详情脱敏不够）
- **禁用账号仍可登录**：status 校验缺失

**说明：** 第 5、6 组多人自研架构常见此问题；基于 starter 的同学多数实现了 JWT，但仍有 `@PreAuthorize` 漏挂（如 `GET /users/{id}` 任意登录用户可查他人）。

### 5. 提交范围与协作边界

- **只交前端或只交后端**：无法验收全栈，分数封顶约 **60～66**
- **同组代码高度雷同**：第 5 组谢晓童/熊禹粒源码几乎相同（LMS 已对熊禹粒 **−10** → **61 分**）；第 7 组张泽宇/蔡光鹏协同项目 55+ 文件 MD5 一致（**−10** → **84/83 分**）；第 10 组张刘荣/左育新同一套代码（**−10** → **86 分**）；第 9 组多份 backend 33 文件逐字节相同 — 答辩需核实贡献
- **误评风险**：仅给 front-end 链接时，不能联评同组织他人 backend（第 3 组已从 88 分纠正为 60 分）

## 四、做得好的地方

### 1. 整体基线较高

多数同学 **基于课程 starter** 完成了可运行的登录 + 用户列表 + 创建 + 禁用，Flyway + MyBatis + 分层包结构（controller / application / domain / mapper）清晰，说明课堂 starter 与教案路径有效。

### 2. 优秀作业的共性（90+ 与 83～89 分档）

以下做法在第 1、8 组 **90+** 仓库及第 10 组 **83～89** 分档中反复出现，可作为 **标杆 checklist**：

- **构建双绿**：`mvn compile` 与 `npm run build` 均通过
- **JWT + `@PreAuthorize`** 覆盖用户写操作与敏感读接口
- **编辑用户**：密码留空不更新（`updateWithoutPassword` 或等价分支）；status 可更新；管理员不可被禁用
- **软禁用** 替代物理 DELETE；列表带分页与 total
- **主题四方对齐**（见第三节清单）；无「工单管理系统」残留
- **Flyway 种子** 含本组 2～4 类业务角色演示账号，密码统一 BCrypt
- **前端事件**：`bindTableActions` 只绑定一次；路由守卫 + axios Authorization 拦截器
- **文档**：独立 `backend/README.md` 写清演示账号、端口、API（第 10 组左育新）

### 3. 自研架构组的亮点

第 4～6 组部分同学未用 starter，但仍有值得肯定之处：

- 目录 README 清晰、Vue + Element Plus UI 完整
- 角色中文标签贴合本组业务（如配送调度员、收购员）
- Service 层清除 password 字段、编辑 SQL 动态不更新 password

短板集中在 JWT 与 Maven 构建链路，可在后续作业强制对齐 starter 的安全与构建配置。
